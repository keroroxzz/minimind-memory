# Looped Transformer：實作與實驗規劃

寫於 2026-07-31，接續深度任務的發現：**29M vanilla 單次前向可做 6 步組合推理（93%）且未飽和**，
而 `use_dense_attention` 買不到深度（k=6 時 93.3% → 54.0%）。

Looped transformer 是 repo 裡**唯一真正增加序列化計算步數**的機制，也是最符合
「用結構換能力、不花參數」命題的一個 —— 但從未被評測過。

最終目標不只是「固定迴圈 k 次」，而是**模型自己決定該想多深**。這份規劃把自適應深度
當成終點來倒推架構，而不是事後外掛。

---

## 1. 現況盤點

`num_loops` 次重跑整個 8 層堆疊，loop ≥ 1 時額外加上 per-loop-index 的 LoRA。

| num_loops | 參數 | LoRA | 有效序列步數 | KV cache 條目 |
|---|---|---|---|---|
| 1 | 28.98 M | — | 8 | 8 |
| 2 | 29.24 M | 0.26 M | 16 | 16 |
| 3 | 29.50 M | 0.52 M | 24 | 24 |
| 4 | 29.76 M | 0.79 M | 32 | 32 |
| 6 | 30.29 M | 1.31 M | 48 | 48 |

**參數面極漂亮**：6 倍深度只多 4.5% 參數。這正是命題要的東西。

**但 KV cache 線性成長**（8 → 48 條目，6×）。這是這個機制真正的價格，必須寫進成本表 ——
在 12 GB 的卡上跑長上下文時，這會是綁定約束，不是參數。

---

## 2. 必須先決定的設計問題

### 2.1 per-loop LoRA 把迴圈次數寫死了 —— 這是最大的損失

`loop_lora_attn` 是以 loop index 為 key 的 `ModuleDict`，範圍 `range(1, num_loops)`。
實測：`num_loops=3` 訓練的權重載進 `num_loops=5` 的模型，**64 個參數不存在**。

代價是失去 **test-time compute scaling** —— 而那正是這條線最值錢的性質：

> 訓練時隨機抽 loop 次數 → 推論時可以對難題多跑幾圈，用推論算力換能力，參數不變。

這對「越級打怪」是直球命中。而且它是**自適應深度的硬前提**：迴圈次數若寫死在參數結構裡，
模型根本不可能在推論時動態決定要跑幾圈。

**決定**：改成
- 一組**共用的** LoRA（所有 loop ≥ 1 共用）
- 加上 **loop-index 的連續嵌入**（正弦編碼，Universal Transformers 的 timestep embedding）

連續訊號才能外推到訓練沒見過的圈數。保留舊行為當對照：`--loop_adapter {per_index, shared, none}`。

### 2.2 沒有 input injection

embedding 只在第 0 圈進入，之後全靠 hidden state 攜帶，圈數一多資訊會衰減。
標準做法是每一圈都重新注入：`h = core(h + input_emb)`。一行的事，圈數越多越重要。

### 2.3 prelude / core / coda —— coda 要薄

```
token embedding → Prelude (layer 0-1, 跑 1 次)
                → Core    (layer 2-5, 迴圈 k 次)   ← 深度來源
                → Coda    (layer 6,   跑 1 次)     ← 保持 1 層
                → norm → lm_head
```

成本（2+4+1、迴圈 6 次）：層執行 `2+24+1 = 27` 次，對比全部迴圈的 48 次，**省 44%**，
而 core 的 24 步推理深度沒有損失。

**coda 必須薄的理由跟停止機制耦合** —— 見 3.2。

## 3. 自適應深度（本規劃的終點）

### 3.1 per-token，不是 per-sequence

早期版本建議 per-sequence（實作簡單）。**那是錯的**，因為它預設了隱式深度會取代顯式 CoT。

實際上兩者並存，而**顯式思維鏈裡多數 token 是語法填充**（「是」、標點、連接詞），
那些不需要深思。per-sequence 會被序列裡最難的那個 token 拖住，等於放棄全部收益。

這也修正了測試台的分工：

| 測試台 | 驗證什麼 |
|---|---|
| 合成深度任務（答案 2 token） | 迴圈買不買得到深度 |
| **Belle CoT（長輸出）** | **per-token 停止省不省得到算力** |

**實作分兩階段，不要跳過第一階段：**

- **階段一（驗證機制）**：算全部，只更新未停止的
  ```python
  h_new = core_block(h)
  h = torch.where(halted[..., None], h, h_new)   # 停止的 token 狀態凍結
  ```
  不省算力，但能回答「多數 token 早退時正確率保不保得住」，並量出潛在可省多少。
  KV cache 不需要 ragged —— 凍結的 token K/V 保持停止當下的值即可。

- **階段二（真的省算力）**：gather 出 active token 只算它們，attention 的 Q 只取 active、
  K/V 用完整 buffer，算完 scatter 回去（即 Mixture-of-Depths 的做法）。

  **機制沒驗證前不要做階段二**，很可能白做。

### 3.2 停止訊號放哪裡：core 首層，不是 coda

兩個候選：

| | KL on 輸出分佈 | **core 首層 halting head** |
|---|---|---|
| 成本 | 每次檢查要跑一次 coda | **零**（本來就要算） |
| 訓練 | 不用，純推論期啟發式 | 要訓練、要平衡 ponder cost |
| 風險 | 無 | ACT 經典失敗模式：塌縮成永遠立刻停 |
| 額外好處 | — | 判斷的計算可直接餵給下一圈 |

把訊號放在 core 首層，等於問「這個 token 值不值得再深思、還有沒有深思空間」，
而且那個計算本來就是 core 前向的一部分 —— 零額外成本。這也是為什麼 coda 可以保持薄：
不需要靠它做退出檢查。

**KL 用熵不如用收斂**：熵量的是「我有多有把握」（模型可以自信地錯），
`KL(p_k ‖ p_{k-1})` 量的是「多算一圈還會不會改變答案」—— 後者才是迭代式精煉該用的訊號。

### 3.3 KL 當老師，halting head 當學生

不要二選一，讓昂貴的那個去教便宜的那個：

1. 先用 **KL 判準**（免訓練）離線跑出每個 token 的最佳退出點 —— 昂貴但正確的參考答案
2. 用那些退出點當**監督訊號**，把 core 首層的 halting head 訓成它的廉價近似

halting head 因此變成**監督式學習**，完全繞開 ACT 那套 ponder cost 平衡的不穩定性，
而且有現成的上界可比：訓出來的 head 離 KL oracle 有多遠。

## 4. 實作順序

| # | 項目 | 工作量 | 是否為自適應深度的前提 |
|---|---|---|---|
| 1 | input injection | 1 行 | — |
| 2 | 共用 LoRA + loop-index 連續嵌入 | 小 | ✅ 硬前提 |
| 3 | 訓練時隨機抽 loop 次數 | 小 | ✅ 硬前提 |
| 4 | prelude/core/coda 切分（coda 1 層） | 中 | ✅ |
| 5 | KV cache 成本量測 | 小 | — |
| 6 | KL 收斂判準（純推論、per-token 階段一） | 小 | 1–4 做完就幾乎免費 |
| 7 | core 首層 halting head（KL 蒸餾） | 中 | — |
| 8 | 階段二 gather/scatter | 大 | 等 6、7 驗證後再說 |

1–3 做完就能跑 E1、E2。加上 4、6 就能跑 E5。

## 5. 實驗規劃

前提：先拿到 k=1..16 的 vanilla 天花板 k\*（進行中）。

### E1（決定性）：迴圈能否推高深度天花板
在 k\* 附近比較 `num_loops = 1,2,3,4`，其餘完全相同。
若 4 圈曲線與 1 圈重疊，代表瓶頸不在深度。成本：4 組 × 約 20 分。

### E2：test-time compute scaling
訓練時 loop 次數從 `{1..4}` 隨機抽，推論時用 1/2/4/8 圈評測。
**同一組權重、不同推論預算、不同能力** —— 這條若成立就是越級打怪最直接的證據。

### E3：進位問題（跨步驟狀態）
十位數正確率一直貼著 10% 基準，這是狀態累積而非深度的問題。
先測純迴圈能不能改善（預測：不能），不行再加跨 loop 的狀態向量。

### E4：成本核算（每個實驗都附）
參數、KV cache 條目、peak VRAM、tokens/s。特別是 KV 的 `num_loops` 倍數。
`use_latent_attention`（cache −25%）加上 core-only 迴圈，可把 6 圈的 KV 從 6× 壓到約 2.2×。

### E5：自適應深度的 Pareto 曲線
畫「平均使用圈數 vs 正確率」，對比固定圈數的基準線。
若自適應在**相同平均算力下**贏過固定圈數，機制就成立。

### E6（機制層面的證據）：圈數是否真的跟難度相關
兩個只有你的測試台做得到的驗證：

1. **合成任務**：畫「平均使用圈數 vs 真實深度 k」。單調上升 = 停止機制真的在分辨難度，
   而不只是調閾值換到 Pareto 的另一點。多數論文因為沒有 ground-truth 難度，驗不了這件事。
2. **CoT 資料**：畫「每個 token 用了幾圈 vs 該 token 的詞性」。若標點與語法詞停在第 1 圈、
   數字與推理步驟用滿圈數 —— 那是機制正確運作的直接證據。

## 6. 預測（先寫下來，避免事後合理化）

1. **E1 會成功但幅度有限**：天花板從 k\* 推到約 1.5–2× k\*，而非線性的 4×。
   29M 的寬度會先成為瓶頸。
2. **E2 是最有機會出漂亮結果的**，前提是實作 2、3 做對。
3. **E3 純迴圈不會改善十位數**。進位需要狀態通道，不是更多變換。
4. **KV cache 會成為實務上的限制**，比參數量早得多。
5. **E6-2（詞性 vs 圈數）會是整條線最有說服力的一張圖**，即使 E5 的 Pareto 增益不大。

如果 1 和 2 都成立，這條線就比 CompleteAttention 有前途得多，
且值得把 `use_dense_attention` 從主線降級成對照組。
